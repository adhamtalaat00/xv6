PROJECT OBJECTIVE
================================================================================
Extend xv6 with three integrated kernel-level security layers required by 
FDA and IEC 62443 for life-critical embedded devices:

1. Role-based user authentication
2. UNIX-style file permissions
3. Syscall audit logging

Target Use Case: Medical wearables (insulin pumps, pacemakers, CGMs)

SECURITY DESIGN DECISIONS
================================================================================

1. PASSWORD HASHING
   - Simplified hash function for demonstration
   - Production would use bcrypt/argon2
   - Passwords never stored in plaintext

2. ROOT PROTECTION
   - Root (uid=0) cannot be deleted
   - Admin bypass for all permission checks
   - System always has at least one admin

3. RING BUFFER AUDIT
   - Fixed 128 entries prevents memory exhaustion
   - Circular buffer overwrites old entries
   - Efficient O(1) logging

4. ADMIN-ONLY AUDIT
   - Only uid=0 can read audit logs
   - Returns EPERM for non-admin attempts
   - Prevents privilege escalation via audit data

5. MEDICAL FILE SECURITY
   - Pre-assigned ownership and permissions
   - Three separate roles: ADMIN, DOCTOR, PATIENT
   - Each role has specific access rights

LIMITATIONS & FUTURE WORK
================================================================================

Current Limitations:
  - In-memory user table (no persistent storage)
  - Simplified password hashing (not cryptographically secure)
  - No group membership beyond primary GID
  - No ACLs or extended security attributes
  - Ring buffer limited to 128 entries

Future Enhancements:
  - Persistent user database with encryption
  - Proper bcrypt/argon2 password hashing
  - POSIX.1e ACLs support
  - SELinux-style mandatory access control
  - Network access control
  - Encrypted file systems
